# Dental Route LP — 現場改善の窓口

歯科医院向けの現場改善窓口 LP（ランディングページ）です。

## 概要・ポートフォリオとしての特徴

- **プロジェクト名**: Dental Route LP
- **概要**: 歯科医院向けの現場改善窓口LP
- **目的**: 強い営業ページではなく、医院側の現状を気軽に共有できる「受け皿」として設計
- **役割**: 自己紹介、ポートフォリオ、および歯科医院向け（予約導線、LINE運用、採用、業務改善など）の相談窓口
- **特徴**: コンプライアンスとセキュリティを最優先し、**患者様情報を一切取得しない**設計を徹底
- **技術スタック**: Next.js (App Router) / TypeScript / Tailwind CSS / API Route / Nodemailer / Vercel
- **フォーム送信**: データベースには保存せず、API Route 経由で直接 Gmail へ通知するセキュアな構成
- **公開状態**: 現在は検証用の**Basic認証あり限定公開**
- **検索設定**: 検索エンジンへの露出を防ぐため、`noindex` / `nofollow` および `robots.txt Disallow: /` を設定
- **関連制作物**: 将来的に「ReservePRO 予約管理デモ」と接続できる導線を構想中

---

## 1. プロジェクトの詳細・運用方針

**Dental Route** は、歯科医院の院長・事務長・運営担当者が「今の状況を気軽に共有できる受け皿」として設計されたサイトです。

- サービスを強く売り込むことは目的としていません
- まず医院側の現状を聞かせていただき、その上で何ができるかを一緒に考えます
- 患者様の個人情報・医療情報は一切取得しません
- 成果を保証する表現は使いません
- 対応できないと判断した場合は、正直にお伝えします

## 6. 環境変数

Vercel の「Environment Variables」に以下を設定してください。  
**コード内への直書き・外部共有は厳禁です。**

```env
# Gmail 送信用（アプリパスワードを使用）
GMAIL_USER=あなたのGmailアドレス
GMAIL_APP_PASSWORD=Gmailのアプリパスワード（16桁）

# 受信先メールアドレス
CONTACT_TO_EMAIL=受信用のメールアドレス

# Basic 認証（検証用の限定公開設定）
BASIC_AUTH_USER=ログインID
BASIC_AUTH_PASSWORD=パスワード
```

### 注意

- `NEXT_PUBLIC_` プレフィックスは **付けないでください**（クライアント側に漏洩するため）
- Gmail アプリパスワードは Google アカウントの「2段階認証」を有効にした上で発行します
- 環境変数を変更した場合は、Vercel の「Deployments」から **Redeploy を行う必要があります**

| 設定 | 状態 |
|---|---|

| robots.txt | **Disallow: /**（全クローラー拒否） |

### 検索公開に切り替える場合（現時点では非対応）

将来的に一般公開・SEO対応する場合は、以下をすべて変更する必要があります。

1. `proxy.ts` で Basic 認証を解除（または環境変数を削除）
2. `app/layout.tsx` の `robots: { index: false }` を `index: true` に変更
3. `app/robots.txt` を `Allow: /` に変更
4. Google Search Console への登録
5. sitemap の追加

> **現時点では上記の変更は行わないでください。**

## 12. 日本語ファイル編集時の注意

このプロジェクトには、日本語テキストを含むページやコンポーネントが多数存在します。
日本語ファイルを修正・更新する場合は、**文字化け（エンコーディングの破損）**に十分注意してください。

### 過去のトラブル事例
過去に、PowerShell の `Set-Content` コマンドを使用して日本語を含むファイルを直接書き換えた際、テキストが意図せず文字化けし、その結果 **Vercel のビルドエラーが発生した**事例があります。

### 編集時のルール
- **PowerShell の `Set-Content` などによる直接的な一括書き換えは避けてください。**
- 文字コードを確認せずに一括置換ツール等を使用しないでください。
- 修正時は、必ず **UTF-8（BOMなし）** が維持されるエディタや方法で編集を行ってください。
- Google Antigravity / Gemini / Claude などの AI アシスタントを利用してコードを修正させる場合も、文字コードを維持できる専用の書き込みツール（`write_to_file` 等）を使うように指示してください。
- 修正作業の完了は、**「日本語表示が正常であること」**および**「Vercel でのビルドが成功していること」**を確認してからにしてください（ビルド確認前に完了扱いにしないこと）。

## 13. Basic認証・proxy.ts 編集時の注意

このプロジェクトでは、検索公開前の限定公開として Basic認証を使用しています。
Basic認証は、Next.js の `proxy.ts` で制御しています。
Next.js 16.2 対応により、従来の `middleware.ts` ではなく `proxy.ts` を使用しています。
そのため、認証まわりを修正する場合は、以下に注意してください。

### 注意点

- **`middleware.ts` と `proxy.ts` を同時に存在させない**
- Basic認証の制御ファイルは `proxy.ts` に統一する
- `proxy.ts` のエクスポート名が、Next.js 側で正しく認識される形（`export function proxy`）になっているか確認する
- 認証関連の関数名、matcher、環境変数参照を不用意に変更しない
- `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` の環境変数名を変更しない
- 環境変数未設定時に認証がスキップされないようにする
- Production 環境でも Basic認証が有効であることを確認する

### 過去に発生した問題

過去に、`middleware.ts` から `proxy.ts` へ移行した際、関数エクスポート名やファイル構成の不整合により、Basic認証が正しく機能しない状態になりました。
また、`middleware.ts` を新規作成して `proxy.ts` と共存したことで、Vercel のビルドエラーが発生しました。
最終的には、`middleware.ts` を削除し、`proxy.ts` に認証処理を統一することで復旧しました。

### 認証確認方法

Basic認証を確認する場合は、通常ブラウザだけで判断しないでください。
ブラウザに認証情報が残っている場合、認証が外れているかどうかを正しく判断できないことがあります。
確認時は以下を行ってください。

- **シークレットウィンドウ**でトップページを開く
- 別ブラウザ、または別端末でも確認する
- `/`、`/areas`、`/results`、`/philosophy`、`/privacy` の各ページで認証が必要か確認する
- 正しいID / パスワードで入れるか確認する
- 認証後、フォーム送信とGmail受信が正常に動くか確認する

### 変更後の確認項目

Basic認証まわりを修正した場合は、以下を確認してください。

- [ ] Vercel のビルドが成功している
- [ ] `ƒ Proxy (Middleware)` として認識されている
- [ ] Basic認証が表示される
- [ ] 正しいID / パスワードで入れる
