# Dental Route LP

歯科医院向けの現場改善窓口 LP（ランディングページ）です。

## 1. プロジェクト概要
- **Dental Route LP** は、歯科医院向けの現場改善窓口LPです。
- 強い営業ページではなく、医院側の現状を気軽に共有できる「受け皿」として設計されています。
- 自己紹介、ポートフォリオ、および歯科医院向け（予約導線、LINE運用、採用、業務改善など）の相談窓口としての役割を持たせています。
- 将来的に「ReservePRO 予約管理デモ」と接続できる導線を構想しています。

## 2. 制作意図
- **ReservePRO** を作成後、それにつながる入口として本LPを作成しました。
- このLP自体も制作物・ポートフォリオの一つとしての役割を担っています。
- テーマ、構想、文章、構成、技術実装まですべて自分で設計・制作しました。
- 制作にあたってはAIを活用しながら開発を進めました。
- 現時点では安全性を最優先し、限定公開・デモ運用という形態をとっています。

## 3. 技術スタック
- **フレームワーク**: Next.js (App Router)
- **言語**: TypeScript
- **スタイリング**: Tailwind CSS
- **バックエンド処理**: API Route
- **メール送信**: Nodemailer
- **ホスティング**: Vercel
- **セキュリティ**: Basic認証
- **通知**: Gmail通知

## 4. 主な機能
- トップページ
- 対応領域ページ (`/areas`)
- 実績・運用例ページ (`/results`)
- 大切にしていることページ (`/philosophy`)
- プライバシーポリシーページ (`/privacy`)
- 状況共有フォーム
- Gmail送信（フォーム内容をメールで通知）
- 送信完了画面（同一ページ内遷移）
- Basic認証（アクセス制限）
- `noindex` / `nofollow`（検索エンジン非表示）
- `robots.txt Disallow: /`（クローラー拒否設定）

### 問い合わせ内容の自動整理機能
フォーム送信内容を固定ルールで分類・整理し、管理者向けのGmail本文に自動で補足情報を追加する機能です。AI機能を想定できる設計・実装力を示すための仕組みですが、**外部AI APIは一切使用していません**。

**【整理・出力される項目】**
- 問い合わせ内容の要約
- 課題分類
- 確認優先度と理由
- 優先して見るべき課題
- 初回ヒアリングで最初に確認すること
- 提案の方向性
- 返信メッセージ案
- 注意書き

**【本機能の重要事項】**
- **外部AI APIなし**（OpenAI API、Gemini API、Amazon Bedrock、RAG連携などは一切不使用）
- **DB保存なし**
- **自動返信なし / 自動送信なし**
- メモや返信文案はあくまで補助であり、最終判断、修正、送信は必ず人間（管理者）が行います。
- 医療判断、診断、治療提案、予約確定を行うものではありません。
- 患者様情報や具体的な診療内容は扱いません。

## 5. セキュリティ・公開方針
- **現在はBasic認証あり限定公開** です。
- **検索公開しない**（`noindex`等の適用）方針です。
- **患者様情報は一切取得しない** コンプライアンス重視の設計です。
- データベースへの保存（DB保存）は行いません。
- 外部チャットツール（Slack等）への外部通知は行わず、**Gmail受信のみ**で運用しています。
- 環境変数はコード内に直書きせず、プラットフォーム（Vercel等）の環境変数設定を使用します。

## 6. 環境変数
以下の環境変数を設定して運用します。**※実際の値はコード内に絶対に記載しないでください。**

```env
GMAIL_USER=
GMAIL_APP_PASSWORD=
CONTACT_TO_EMAIL=
BASIC_AUTH_USER=
BASIC_AUTH_PASSWORD=
```

## 7. GitHub共有時の注意
- 現時点では**外部共有予定はありません**。
- 将来的に共有する場合は、事前に機密情報が含まれていないか必ず確認してください。
- `.env` 系のファイル（`.env.local` 等）は絶対に含めないでください。（`.env.example` のみ共有可）
- 実在の医院名、個人名、患者情報、内部URLをコードやコミット履歴に含めないでください。
- README にも実際の認証情報やパスワードを書かないでください。

## 8. 保守時の注意
以下の処理・設定は、システムの根幹およびセキュリティに関わるため**不用意に変更しないでください**。

- フォーム送信処理
- API Route (`app/api/contact/route.ts`)
- Gmail送信処理
- Basic認証ロジック
- `proxy.ts`
- `noindex` / `nofollow` 設定 (`app/layout.tsx` 等)
- `robots.txt`
- プライバシーポリシー本文
- **患者様情報を取得しない方針**（注意書きや仕様変更など）

## 9. 日本語ファイル編集時の注意
- PowerShell の `Set-Content` 等による日本語ファイルへの直接書き換えは避けてください。
- 文字コードは必ず **UTF-8（BOMなし）** を維持してください。
- 過去に文字化けが発生し、Vercel のビルドエラーが起きた事例があるため、エディタでの保存時などに注意してください。

## 10. Basic認証・proxy.tsの注意
- Next.js 16.2 対応のため、Middleware として `proxy.ts` を使用しています。
- ビルドエラーの原因になるため、**`middleware.ts` と `proxy.ts` を共存させない**でください。
- Basic認証の確認時は、キャッシュの影響を避けるため**シークレットモード（プライベートブラウズ）**で確認してください。
- デプロイ時は、Vercel のビルドログで `ƒ Proxy (Middleware)` として認識されていることを確認してください。
